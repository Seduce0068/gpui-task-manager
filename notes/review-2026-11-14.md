## 3. セキュリティ（敵対的レビュー）

### 3.1 major

#### M1. ブラウザ用トークンをクエリ文字列で受け付けており、URL 経由の漏洩面がある

- 根拠: `agent/src/auth.rs:92-100` が `?token=` を受理し、`agent/src/main.rs:270-280` がその値を認証に使う。Runtime Proof で `?token=test` が 200 を返すことを確認。`DESIGN.md:413` はブラウザ版の接続方法として `?agent=http://127.0.0.1:18787&token=<token>`（ページ URL にトークン）を案内している。URL のトークンはブラウザ履歴・Referer・スクリーンショット・共有 URL から漏れ得る（CWE-598 相当）。
- 影響: トークンは読み取り専用 API の鍵であり、漏洩しても操作系はないが、プロセス一覧・コマンドライン・ユーザー名の全量が同一マシンの任意プロセスから読める。
- 修正案: (a) クエリ受け付けを削除して `Authorization: Bearer` のみにする（fetch はヘッダを送れる）、(b) どうしても必要な場合（EventSource 等）は短命・単回使用の専用チケットを別エンドポイントで発行する、(c) `DESIGN.md` のブラウザ接続例をヘッダ方式へ変更する。`web/` は対象外のため、最終的にどちらの方式を採るかは web 側と合わせて確認が必要。

#### M2. 「短命トークン」という設計記述と実装が一致しない

- 根拠: `DESIGN.md:317-318` は残余リスクの緩和として「ループバック + **短命トークン**で影響を限定する」と書くが、トークンは起動時に 1 回生成され（`agent/src/auth.rs:26-35`、`agent/src/main.rs:92-101`）、期限・ローテーション・失効の実装はない（プロセス生存中は不変）。
- 影響: セキュリティ設計の主張が実装より強い。AC-12（設計書と実装の一致）を満たさない。
- 修正案: TTL とローテーションを実装するか、`DESIGN.md` を「プロセス生存中の固定トークン。漏洩時は再起動で無効化」と正確に修正する。後者なら「短命」の語を削除する。

#### M3. 確認ダイアログは Enter で即確定し、設計が掲げる「既定フォーカスはキャンセル側」が実装されていない

- 根拠: `app/src/app.rs:235-241` は `pending_kill` がある間、`enter` を `Command::ConfirmKill` に、`escape` をキャンセルに割り当てる。フォーカス制御はなく、`kill_dialog`（`app/src/app.rs:1222-1302`）にも既定ボタンの概念がない。一方 `DESIGN.md:227-228` は「既定フォーカスはキャンセル側に置く」と書く（同じ行の括弧内では「MVP では Enter で確認」と矛盾する記述になっている）。
- 影響: 破壊的操作（SIGTERM/SIGKILL）の確認で、キー 1 回（Enter）が確定になる。誤操作時にプロセスを失う。設計書の安全側デフォルトの主張が成立していない。
- 修正案: 既定をキャンセルにする（Enter = CancelKill、確定は Tab 移動 + Enter か明示クリック）。少なくとも `DESIGN.md:227-228` を実装に合わせて修正し、MVP の制約として明記する。

### 3.2 minor

- **s1. シリアル処理によるローカル可用性低下**: `agent/src/main.rs:150-162` は 1 接続ずつ処理し、`agent/src/http.rs:22-26` の 5 秒 read timeout まで待つ。Runtime Proof で無送信接続 1 本が `/healthz` を 4,499 ms 遅延させた。ローカル DoS は成立するが影響はエージェントの可用性のみ。修正案: スレッドプール化、または「ヘッダ受信は短い timeout（例 1 s）」+ 同時接続数上限。少なくとも既知の制約として文書化する。
- **s2. Host ヘッダ未検証（DNS リバインディング多層防御の欠落）**: `agent/src/http.rs:94-151` のパースと `agent/src/main.rs:204-229` のルーティングは `Host` を見ない。Runtime Proof で `Host: evil.example` + 正トークンが 200。トークン必須のため実害は限定的だが、ブラウザ由来の攻撃面を考えるなら Host を `127.0.0.1`/`localhost` に限定するのが定石。修正案: `Host` が loopback でなければ 421/403。
- **s3. CORS 許可範囲が設計記述より広い**: `agent/src/http.rs:233-262` は任意ポートに加えポートなしの `http://127.0.0.1` / `http://localhost` も許可する（`agent/src/http.rs:261`、テストは `agent/src/http.rs:408-435`）。`DESIGN.md:257` は `<port>` 付きのみと記載。修正案: 実装を設計に合わせるか、設計に「ポートなしも許可」と明記。
- **s4. トークンの露出経路が argv と stderr にある**: `agent/src/args.rs:89-95` の `--token` は `/proc/<pid>/cmdline` から同一マシンの他プロセスに読まれ得る。生成トークンの stderr 出力（`agent/src/main.rs:92-101`）は端末スクロールバックや systemd journal に残る。修正案: `--token-file` / 環境変数 / stdin を用意し、README の `--token test`（`README.md:58`）は「テスト専用・使い捨て」と明示する。
- **s5. `/dev/urandom` 失敗時の fallback が弱い**: `agent/src/auth.rs:47-68` は時刻と PID の SplitMix64 で 32 バイトを生成する（実効エントロピーは 64 bit 程度）。コードコメントで「弱い」と明示している点は良いが、起動時に警告を出す・失敗として終了する選択肢を推奨。
- **s6. `Authorization` ヘッダが不正だとクエリトークンへ fallback しない**: `agent/src/auth.rs:93-98` の `split_once(' ')?` が関数全体から早期 return するため、`Authorization: Bearer`（空白なし）付きの正当な `?token=` 要求が 401 になる（Runtime Proof で再現）。修正案: `if let Some((scheme, value)) = ...` にして fallback を維持。テスト追加も必要。
- **s7. PID 再利用防御の残余（秒精度 + TOCTOU）**: `crates/tm-platform/src/lib.rs:392-412` は送信直前に start_time を照合するが、(a) `start_time` は秒精度（`sysinfo 0.40.3` は epoch 秒。`crates/tm-core/src/model.rs:9-22` の記述は正しい）、同一秒内の PID 再利用では照合を通過し得る、(b) 再取得から `kill_process` まで原子的でない。ADR-007（`DESIGN.md:510-515`）は「大幅に下げる」と正直に書いており blocker ではないが、残余リスクとして `DESIGN.md` に明記し、可能なら `pidfd` 系 API を検討する価値がある。
- **s8. `user` フィールドだけサニタイズされていない**: 名前・コマンド・ホスト名・IF 名・マウントポイントは `sanitize_display` を通す（`crates/tm-platform/src/lib.rs:108-111, 263-277, 326, 348-351`）が、`user` は生のまま（`crates/tm-platform/src/lib.rs:278-282`）で UI 表示される（`app/src/app.rs:857, 940, 998-1000`）。`/etc/passwd` 由来の名前は通常制約されるが、NSS 経由で制御文字を含み得る。修正案: `sanitize_display` を適用（`MAX_NAME_CHARS`）。
- **s9. 表示なりすましの残余（推測を含む）**: `crates/tm-core/src/sanitize.rs:20-67` は制御文字・ANSI・bidi 制御を除去するが、ゼロ幅文字・結合文字・同形異義文字（例: Cyrillic の `ѕ`）は残る。PID 併記とダイアログのプロセス名表示で緩和されるが、名前ベースの誤認は可能。修正案: ゼロ幅/異体字セレクタの除去を追加（過剰除去は正当な名前を壊すため方針判断が必要）。
- **s10. モーダル overlay のクリック透過（推測）**: `app/src/app.rs:1230-1239`（確認ダイアログ）と `app/src/app.rs:1346-1355`（ヘルプ）の overlay は背景色だけで `on_click`/`occlude` を持たない。GPUI の hit-test 実装を確認していないため**推測**だが、背後の行・シグナルボタンがクリック可能だと、ダイアログ表示中に別操作が成立する。修正案: overlay に `occlude()` または no-op の `on_click` を付ける。
- **s11. README の弱いトークン例**: `README.md:58` の `--token test` はそのまま常用されると総当たり可能（64 bit 未満）。テスト用であることと、常用時は生成トークンを使うことを明記する。

### 3.3 良い点（確認済み）

- シグナル送信は `rustix::process::kill_process` の安全 API のみで、自コードに `unsafe` はない（`grep -rn unsafe` で `#![forbid(unsafe_code)]` 以外の使用なし）。PID 0/1/自分自身の拒否は viewmodel（`crates/tm-viewmodel/src/lib.rs:246-254`）と platform（`crates/tm-platform/src/lib.rs:379-385`）の二重で実装されている。
- 認証は 32 バイト乱数 + 定数時間比較（`agent/src/auth.rs:74-85`）。401 応答に `WWW-Authenticate: Bearer`、`Cache-Control: no-store`、`X-Content-Type-Options: nosniff`、`Connection: close` が付く（`agent/src/http.rs:198-231`）。
- エージェントに操作 API は存在せず、`--listen` のループバック強制は bind 前に検証される（`agent/src/args.rs:112-117`、Runtime Proof で exit 1）。
- ヘッダ CR/LF/NUL の混入は拒否され、Origin 反射値は loopback に限定されるためヘッダインジェクションは成立しない（`agent/src/http.rs:126-142, 238-262`）。
- `cargo audit` の「脆弱性 0 / unmaintained 8 件（GPUI 由来）」は本レビューでも再現できた（DB は `--no-fetch` のキャッシュ、鮮度は未確認）。

- **a1. 依存方向の図が実際の Cargo.toml と食い違う（3 箇所）**: 実依存は `tm-platform → tm-core`、`app → tm-platform`（`cargo tree` で確認）。しかし `README.md:75-83` と `crates/tm-core/src/lib.rs:12-20` は platform を shells の下に置き「shells → platform」と読める図になっており、`DESIGN.md:55-76` も core→platform の下向き矢印になっている（規則文 `DESIGN.md:78-85` は正しい）。修正案: `app → tm-platform → tm-core`、`web → tm-core + tm-viewmodel`（platform 非依存）を明示した図に直す。
- **a2. `tm-platform` が未使用の serde / serde_json を宣言している**: `crates/tm-platform/Cargo.toml:11-13` は `tm-core` の `serde` feature と `serde`/`serde_json` を有効化するが、`crates/tm-platform/src/lib.rs` に serde の使用はない（grep で確認）。不要な feature 有効化は wasm/依存最小化の方針（ADR-009）と逆行する。修正案: 3 行を削除し、serde が必要な `agent` 側だけで有効化する。
- **a3. UI 側に保護判定の重複**: `app/src/app.rs:285-298` の Ctrl+K が `is_protected` を再チェックしている。viewmodel の `request_signal` が同じ判定を持つ（`crates/tm-viewmodel/src/lib.rs:395-422`）ため冗長。しかもショートカット経由では保護時のエラーメッセージが出ない（`handle_command` を呼ばないため）。修正案: シェルは常に `Command::RequestSignal` を投げ、判定とメッセージは viewmodel に一本化。
- **a4. テスト欠落（重要度順）**: (a) `DESIGN.md:341` は「`format_clock` は固定入力でテスト」と書くが、`app/src/theme.rs:52-60` にテストはなく、`app` crate のテストは 0 件（Runtime Proof: `test result: ok. 0 passed`）。(b) viewmodel に `RequestSignal`（存在しない key）、`ClearFilter`、`ToggleDetails`、PID 0 保護のテストがない。(c) agent に s6 の「不正 Authorization + 有効 query token」の回帰テストがない。(d) s1 のシリアル阻塞を検知するテストがない。修正案: 上記 4 点を追加（特に (c) は今回の Runtime Proof で実バグを確認済み）。
- **a5. `PlatformInfo` の capability が実態より強い**: `crates/tm-platform/src/lib.rs:99-131` は `Networks`/`Disks`/`Users` の初期化失敗を `None` で握りつぶすが、`platform_info()`（`crates/tm-platform/src/lib.rs:365-368`）は常に `supports_network`/`supports_disks = true`、`supports_process_control = true` を返す。修正案: 実際の `Option` 状態を反映する（ADR-007 の「start_time 非提供プラットフォームの表現」とも整合）。
- **a6. ネットワーク集計が lo / 仮想 IF を含む**: `crates/tm-viewmodel/src/lib.rs:326-341` は `SystemSnapshot::network_totals()`（`crates/tm-core/src/model.rs:238-248`）ですべての IF を合算する。実機では `lo` / `docker0` / `tailscale0` / `br-*` / `lxcbr0` / `virbr0` が混在（Runtime Proof）し、ブリッジ経由の通信が二重計上され得る。RESEARCH 自身が「仮想 IF が混ざる。フィルタが必要」（`RESEARCH.md:126`）と書いているが未実装。修正案: 表示用集計から `lo` と仮想 IF を除外、または IF 別表示にする。
- **a7. ディスクの擬似マウントが未フィルタ**: `crates/tm-platform/src/lib.rs:337-362` は全マウントを返す。実機では `/var/lib/docker/rootfs/overlayfs/...` が十数件と `/var/lib/lxcfs` が含まれた（Runtime Proof）。UI は `app/src/app.rs:385-396` で先頭 2 件しか出さないため実害は小さいが、RESEARCH §3.2-6（`RESEARCH.md:125`）の「フィルタが必要」が未対応。修正案: overlay/tmpfs/lxcfs を除外するか、`/` と実ブロックデバイスのみに限定。

- **a13. `DESIGN.md:319-320` の bidi 残余記述が実装と不一致**: 「MVP では制御文字除去まで、将来は bidi 制御文字も除去」とあるが、`crates/tm-core/src/sanitize.rs:62-67` は既に bidi 制御文字を除去し、テストもある（`crates/tm-core/src/sanitize.rs:122-126`）。修正案: 記述を実装に合わせる。

## 5. 運用・ドキュメント

### 5.1 major

#### M4. 「全プロセス JSON 2.24 MB」が現在の実装と桁違いに不一致（設計判断の根拠が古い）

- 根拠: `DESIGN.md:262`、`DESIGN.md:368`、`DESIGN.md:487`、`RESEARCH.md:31`、`RESEARCH.md:132`、`RESEARCH.md:210` が「全プロセス JSON 2.24 MB」を根拠にページングを正当化する。しかし本レビューの実測は **618 プロセスで 173,454 B（約 0.17 MB）**、既定 500 件で 136,678 B（§2）。原因は `notes/crates-survey.md:164` / `notes/solutions-survey.md:24,245,359` の 2.24 MB が **スレッド込み 3,549 エントリ時点**の測定値であり、スレッド除外修正（`log.md:20`）後に再測定されていないこと。
- 影響: `?limit` の設計自体は妥当（大規模マシン・将来のフィールド追加に備える）が、数値根拠が誤り。性能記述の信頼性が損なわれる。
- 修正案: 現行実装で再測定し、`DESIGN.md` / `RESEARCH.md` の全 6 箇所を更新。2.24 MB は「スレッド込み 3,549 エントリの旧測定」と注記して残すか削除する。あわせて「2.24 MB のためページング必須」という因果を「大規模環境でも 1 秒間隔の全件送信を避けるため」に書き換える。

#### M5. `notes/verification.md` の Runtime Proof 数値が証拠画像と一致しない

- 根拠: `notes/verification.md:38-39` は「CPU 41.0%、メモリ 77.5%（48.6 GiB / 62.7 GiB）、ネットワーク 22.2 KiB/s 受信 / **537.3 KiB/s** 送信、負荷 12.16 / 11.30 / 10.79」と、`notes/assets/task-manager-native-wayland.png` を引用して記載する。しかし同画像の実表示は **CPU 36.9%、メモリ 76.2%（47.8 GiB / 62.7 GiB）、22.2 KiB/s 受信 / 361.1 KiB/s 送信、負荷 16.64 / 11.53 / 9.80**（画像を目視確認）。プロセス数 622・ホスト名・カーネル・PID 1 の詳細は一致。
- 影響: Runtime Proof の再現性・証拠整合性が崩れる。動的な値なので「別時刻のサンプル」を画像の説明として書いていることになる。
- 修正案: 画像と同一サンプルの値に修正するか、数値を削除して「画像参照」に一本化する。再取得する場合は画像と文章を同時に更新する。

#### M6. 個人情報（ホスト名・ユーザー名・ホームパス）が公開物に残っている

- 根拠: `README.md:9` が埋め込む `notes/assets/task-manager-native-wayland.png` に、ホスト名 `<host>`（ヘッダ・システムカード）、ユーザー名 `user`（ユーザー列）、`/home/user/...`（コマンド列）が写る（目視確認）。`notes/verification.md:37` はホスト名を本文に明記。`crates/tm-core/src/demo.rs:125,144,204,214,224` などはデモデータに実ユーザー名と実ホームパスを使用し、デモ画像（現行は `notes/assets/web-shell-01-initial-demo.png`）にも `user` が表示される。`DESIGN.md:188` のモック図にも `user`。
- 影響: リポジトリを公開・共有した場合に、ホスト名・ユーザー名・ディレクトリ構成が露出する。セキュリティ脆弱性ではないが、マージ前ゲートで潰すべき衛生問題。
- 修正案: (a) 画像をマスク（ホスト名・ユーザー列・ホームパスをぼかす）して差し替える、(b) `verification.md` のホスト名を `<host>` に伏せる、(c) デモデータを `user` / `/home/user/...` に置換する（テストは PID・key のみ依存するため影響は小さい）。

#### M7. リポジトリにコミットが存在せず、「Cargo.lock コミット / 完全ピン」の運用前提が未成立

- 根拠: `git log` は `fatal: your current branch 'master' does not have any commits yet`、`git remote -v` は空、`git status --porcelain` は 6 件の未追跡（トップレベル）のみ。`Cargo.lock` は存在し `.gitignore` にも入っていないが、**未コミット**。`README.md:117` は「依存は完全ピン + `Cargo.lock`」、`DESIGN.md:305` は「完全一致ピン + `Cargo.lock` コミット」、`RESEARCH.md:156` も同様に主張する。
- 影響: 供給網統制の主張が現状のツリーでは成立しない。レビュー対象のリビジョンも特定できない（マージ前ゲートとしての前提が欠ける）。コードの blocker ではない。
- 修正案: マージ手順として初期コミット（`Cargo.lock`・`.gitignore`・`.github/` を含む）を作成し、レビュー対象 commit hash を記録する。`git add -A` 前に `app/native-libs`（§5.2）が混入しないことを確認する。

#### M8. CI がワークスペース運用と異なる org の reusable workflow を参照している（未検証）

- 根拠: `.github/workflows/ci.yml:22` は `uses: Seduce0068/workflows/.github/workflows/rust-gates.yml@v1` を参照する。一方、ワークスペース共通指示（`AGENTS.md` §5）は「提供側は private リポジトリ `旧アカウント名/workflows` の `rust-gates.yml`、参照はタグ `v1`」と定めている。org 名が一致しない。
- 影響: マージ後に CI が起動しない（参照先が存在しない/権限がない）可能性がある。ただし外部リポジトリの実在・可視性は本レビューでは確認していない（**未確認**）。また未コミットのため CI 実行実績もない。
- 修正案: `旧アカウント名/workflows/.github/workflows/rust-gates.yml@v1` に修正し、初回 push 後に CI が実際に走ることを確認する。ローカル代替として `cargo fmt --check` / `cargo test` / `cargo clippy -D warnings` / `cargo audit` は本レビューで成功済み（§2）。
